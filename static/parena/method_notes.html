Method & validation notes

What 0.4.1 adds

A single upload-to-report workflow, training-fold missing-value handling, optional training-only feature-outlier deletion, and a new classification interface. Regression retains the frozen 0.4.0 candidate pool; the interactive setting declares a smaller pool to control CPU time.

Core and auto

Core learns measured response differences between neighboring observations and combines anchor-based reconstructions. Auto selects or combines core and baseline predictions using training-side validation. A higher version number does not establish higher predictive accuracy.

Classification

For each class c, use t_ic = 1[y_i = c]. Pair targets are t_ic − t_jc. Each training point also connects to its two nearest opposite-class anchors to represent class boundaries. Each class obtains an anchor reconstruction, clipped to [10⁻⁶, 1] and normalized across classes. A temperature in {0.5, 1, 2} is chosen on training-side out-of-fold probabilities. Auto searches a convex core/baseline combination with weights {0, .25, .5, .75, 1}. The new classification extension requires broader external validation.

Evaluation and data treatment

One approximately 20% group-disjoint outer holdout; three-fold inner model selection. Missing predictors use training-fold medians; all-missing training columns use zero and are flagged. Missing targets are reserved for prediction. Nonfinite target measurements are rejected.

The optional deletion rule is feature-only: continuous columns with more than five distinct finite values are flagged outside [Q1 − 3 IQR, Q3 + 3 IQR]. Zero-IQR and discrete columns are exempt. Training folds fit their own rules; held-out rows remain in evaluation. This heuristic is a user-controlled sensitivity choice and can remove scientifically meaningful rare observations.

Standardizing input is optional. PARENA always standardizes its distance representation. Regression predictions return to the original target units. Classification probabilities include training-side temperature selection.

The webpage reports one split, not statistical significance. Broad 0.4.0 regression benchmark scores are not transferred to the 0.4.1 interactive configuration.

Read the visualizations correctly

SHAP uses an explicit CatBoost response guide fitted on training labels. It explains that guide, not the full PARENA ensemble. Dataset PCA is fitted only on training features. Pair PCA visualizes the actual pair-feature inputs of the first selected core component; its coordinates are different from the original-data PCA. Pair counts are dependent relationships, not additional independent measurements or newly generated molecules.

Relation to TabPFN

The workflow takes inspiration from unified tabular prediction interfaces and automated preprocessing. PARENA implements task-specific pairwise learning on a CPU; it has no TabPFN architecture, pretrained weights or in-context transformer. “End-to-end” here describes workflow automation from a table to a report.

Reference: Hollmann et al., “Accurate predictions on small data with a tabular foundation model”, Nature 637, 319–326 (2025), doi:10.1038/s41586-024-08328-6. The locally reviewed TabPFN library (6.0.6) is newer than the Nature paper implementation.

Privacy and reproducibility

The public page contains static assets and public-safe examples. Upload requests go to 127.0.0.1 on the user's own computer. No EP records, research results or uploaded measurements are included in the public site. A session key protects the local API. Close the local server when finished; analysis outputs remain in local_results/.

The ZIP records the seed, settings, entity split, predictions, selected configurations, SHAP values, pair-parent provenance and plots. For publication, evaluate repeated group or domain splits with equally tuned baselines and fixed policies.
