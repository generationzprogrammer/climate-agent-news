# 阿里云正式网站部署步骤

适用版本：2026年11月2日。保留现有GitHub Pages；GitHub Actions继续采集、翻译、生成简报，再将同一份公开网站上传阿里云。无需购买ECS，也不需要自己的电脑每天运行。

## 1. 确认域名和节点

登录阿里云控制台，在“域名”中确认已购买的域名完成实名认证。建议先使用 `www.你的域名`，COP31入口为 `https://www.你的域名/cop31/`。

如果需要近期完成国际会议展示，可选中国香港OSS节点；如果选择北京等中国内地节点，域名须先完成ICP备案。香港节点绑定域名无需ICP备案，但中国内地访问的跨境延迟仍需实测。OSS按存储、请求和流量计费，并非永久免费；先设置费用预警，不必开通CDN或购买服务器。[阿里云域名绑定说明](https://help.aliyun.com/zh/oss/user-guide/access-buckets-via-custom-domain-names)

## 2. 创建专用网站Bucket

控制台搜索“对象存储OSS” → Bucket列表 → 创建Bucket。名称自定，例如 `green-public-site`（名称必须全局唯一，以实际创建成功的名称为准）。

- 地域：中国香港；存储类型：标准存储；冗余类型按最低适用配置选择。
- 读写权限：公共读；关闭“阻止公共访问”需要确认这是**只存网站公开文件**的专用Bucket。匿名访问只允许读取，绝不能公共写。
- 不放订阅邮箱名单、密钥、人员原始文件、源代码仓库或SQLite数据库。

## 3. 开启静态网站

进入Bucket → 数据管理 → 静态页面 → 设置：默认首页 `index.html`；**开通子目录首页**；文件404规则选 **Redirect**。这样 `/cop31/` 才会打开独立页，而非误回主站。不设置把所有不存在的数据文件重写成首页的单页应用规则。[官方静态网站步骤](https://help.aliyun.com/zh/oss/user-guide/hosting-static-websites)

## 4. 绑定域名和HTTPS

Bucket配置 → 域名管理 → 绑定域名，填写 `www.你的域名`。按页面提示验证所有权。进入阿里云“云解析DNS”，给域名添加CNAME：主机记录 `www`，记录值复制OSS提供的**域名绑定目标**，不带 `https://` 和路径。

回到OSS域名管理，为该域名开启证书托管，上传或申请适用的TLS证书并配置HTTPS。阿里云证书产品和有效期可能变化，以控制台报价为准。[HTTPS配置](https://help.aliyun.com/zh/oss/user-guide/access-oss-by-https-protocol)

不要把Bucket默认网址当正式网址：默认域名访问HTML可能触发下载，这是OSS安全限制。

## 5. 创建最小权限上传身份

控制台搜索“RAM访问控制” → 用户 → 创建专用用户，例如 `green-site-publisher`，只用于GitHub网站上传，不使用阿里云主账号密钥。为该用户创建AccessKey，并将下列自定义权限中的 `你的Bucket名` 替换为实际名称后授权：

```json
{
  "Version": "1",
  "Statement": [{
    "Effect": "Allow",
    "Action": ["oss:PutObject"],
    "Resource": ["acs:oss:*:*:你的Bucket名/*"]
  }]
}
```

上传程序不需要删文件、修改Bucket配置或读取订阅名单。AccessKey只复制到下一步GitHub Secrets；不发聊天、不截图公开、不写本地脚本。若泄露立即禁用并轮换。

## 6. 在GitHub配置变量与密钥

进入 `generationzprogrammer/climate-agent-news` → Settings → Secrets and variables → Actions。

在 **Secrets → New repository secret** 中新增：

|统一名称|填写值|
|---|---|
|`ALIYUN_OSS_ACCESS_KEY_ID`|RAM用户的AccessKey ID|
|`ALIYUN_OSS_ACCESS_KEY_SECRET`|对应AccessKey Secret|

在 **Variables → New repository variable** 中新增：

|统一名称|中国香港示例|
|---|---|
|`ALIYUN_OSS_BUCKET`|实际Bucket名称|
|`ALIYUN_OSS_ENDPOINT`|`https://oss-cn-hongkong.aliyuncs.com`|
|`ALIYUN_OSS_REGION`|`cn-hongkong`|
|`ALIYUN_OSS_DEPLOY`|`true`|
|`CLIMATE_SITE_HOSTNAMES`|`generationzprogrammer.github.io,www.你的域名`|

Variables里不放任何密钥。若选择其他地域，Endpoint与Region要同时按该Bucket概览中的值更换，不能混用香港示例。

## 7. 打通新域名的问答与订阅

现有服务正常工作不等于自动接受新网站来源。在已有订阅和问答Cloudflare Worker中，将 `https://www.你的域名` 加入**前端公开接口的Origin白名单**，保留原GitHub Pages来源；如启用Turnstile，也添加新hostname。不要关闭订阅后台管理接口的Token校验，不要把管理员Token放进前端。网站部署到阿里云不会自动解决某些网络无法访问 `workers.dev` 的问题；若仍失败，应给服务绑定可达的自定义API域名，再更新公开服务端点。

## 8. 统一访问统计

Cloudflare → Web Analytics中配置正式域名，取得公开beacon token。在GitHub **Variables** 新增 `ALIYUN_WEB_ANALYTICS_SITE_TOKEN`，填正式域名的公开token。上传程序只在OSS版本的HTML中替换统计标识，主站与COP31都使用该标识；GitHub Pages仍用原来的 `CLOUDFLARE_WEB_ANALYTICS_SITE_TOKEN`。两个站点应位于同一Cloudflare账号，账号读取权限的现有Secret仍只在Actions中使用。公开beacon token不是API管理密钥，不要填错。

`CLIMATE_SITE_HOSTNAMES`让后台按多个hostname聚合页面访问量；主站、能源页、COP31使用同一统计口径。不跨域识别自然人，不宣称能把同一个人的不同设备去重。曲线随自动任务刷新，不是网页打开后即时变化。

## 9. 首次发布并验收

GitHub → Actions → “每日更新气候文本数据平台” → Run workflow → Branch选 `main`。不需要为这次部署勾选邮件发送。等“同步阿里云正式网站 配置后启用”和Pages部署都成功。

分别打开 `https://www.你的域名/` 与 `https://www.你的域名/cop31/`，检查：中文和英文切换、语料检索、研究工具、当日PDF、订阅提交、问答、手机显示。直接打开 `/data/research_catalog.json` 检查生成日期和语料数量；如果看到HTML而不是JSON，检查OSS子目录/404规则，不要误以为数据接口正常。

之后现有每日定时工作流会自动更新**两个网站**，不需要手工上传。GitHub定时任务可能排队；应保留失败通知并查看最后成功时间。上传程序只上传生成的 `site/`、拒绝明显私密文件、不删除历史公开文件，数据与HTML最多缓存5分钟。需要暂停阿里云上传时，将 `ALIYUN_OSS_DEPLOY` 改为 `false`，原GitHub Pages仍可使用。

## 常见问题

- **403**：检查公共读权限、阻止公共访问开关、RAM PutObject资源范围和地域。
- **HTML被下载**：用绑定好的自定义域名访问，核对Content-Type为text/html。
- **COP31变成主站**：开通子目录首页，地址保留最后的 `/`。
- **日期没更新**：看Actions是否成功；排查OSS上传步骤、浏览器缓存、是否访问了旧Bucket/CDN。
- **只有访问曲线无数据**：先确认正式站页面有适用beacon，再检查Cloudflare hostname配置与读取权限；不能用生成的假数补齐。
