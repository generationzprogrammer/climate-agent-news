全球气候治理全文语料采集与交接规程
版本：2026-11-06

一、研究范围与计数单位
采集起点为1992年1月1日，终点为本次运行冻结时间。研究对象为与气候治理、能源转型及其实施条件相关的新闻、评论和机构新闻。正文以出版方实际发布的文本为准，不用模型生成文字填充缺失内容。完整性筛选通过的文章、待复核记录、整期期刊、无日期项目说明分别保存和统计。一个PDF文件的多个页面不拆算为多篇新闻。

已有语料的原始文件保持不变。原库找回正文、新增公开来源正文、历史期刊与定向补充记录保留各自来源批次。新快照按规范化正文哈希与规范化网址去重，重复关系写入lineage表。相同事件的不同报道仍可能同时存在；论文分析时还需按研究问题进行事件级聚类。

二、采集流程
1. 从出版方网页发现公开API，检查访问规则和正文可用性；没有适用API时使用普通网页，历史扫描件使用OCR。
2. 冻结起止时间，分页获取。保存请求结果、来源标识、原始批次、正文哈希、提取状态及每页检查点。中断后从检查点继续。
3. 检查题名身份、来源日期、正文块覆盖、结束位置、相关性及重复情况。拒绝登录页、反爬页面、无关促销和明显截断内容。
4. 对末尾“相关阅读”、图片署名、作者信息造成的误报进行有依据的复核；记录复核原因，原文字节不变。复核不足的记录留在待核验层，不混入合格计数。
5. 对每个出版方抽取已获取页面，比较API正文与公开文章页面。保存正文长度比、词组覆盖率及可复核原网页。抽查通过不等于逐篇人工确认。
6. 统计国家、议题和年份缺口，定向检索补充；检索提示不能直接转成文章标签。无法取得可靠正文的缺口如实保留。

采集只使用公开入口，不绕过登录、付费墙、人机验证或访问限制。网络请求有超时、主机间隔和失败记录。运行没有付费模型调用；英文历史扫描材料使用本地OCR。正文保存不代表获得公开再分发许可。

三、标签体系
采用14个一级议题、83个二级议题。用户提供的图片分项数量合计83；图片末尾的77不作为实际字典长度。G12.04—G12.06及G14.01—G14.06为经用户授权补充的9项，其余来自提供的分类内容。这是一套研究分类，不是UNFCCC官方分类标准。

国家和地区使用ISO alpha-2、alpha-3代码。名称出现、标题或导语中的重点候选、机构、政策工具、实施阶段分别存储。针对歧义名称保留上下文条件，例如Jersey不能仅凭普通单词匹配。来源所在国不自动等于报道涉及国。
代码表采用本次项目所用的现行地区口径。跨年代研究需另行处理历史政体、独立时间和边界变更，不能直接把现行代码解释为历史疆域。

每条标签附正文或标题中的证据位置，start从0计数，end为不包含的结束位置；位置单位为Unicode字符，不是UTF-8字节。证据须能回读为完全相同的原文。主题采用可审计词汇和上下文规则，标签属于机器候选，不能当作已经独立人工验证的国家立场、因果关系或外交合作关系。未命中可靠证据时允许不分类。

四、时间与历史材料
区分原始日期、标准化发表日期、时区信息、日期精度及采集时间。只有年月的材料不补造日。文章中提到1992年不能作为1992年发表的证据。

1992年6月《Acid News》第3期第14页的“Chief stumblingblock”有完整页面、期刊日期和作者。保存原PDF、页面图像、英文OCR框、阅读顺序及修正记录。按三栏顺序拼接文章，排除插画、图注、重复引语和页脚；只计一篇文章。视觉核验由助手完成，未宣称独立人工复核。其余未确认阅读顺序或期号身份的整期期刊不计为合格新闻。

五、交接数据结构
climate_governance.sqlite：全文、标签、证据、来源关系和输入文件指纹。
original_recovery.jsonl.gz：通过筛选的原库正文记录。
new_library.jsonl.gz：通过筛选的新增来源及历史单篇记录。
review_required.jsonl.gz：仍需复核的记录，不能默认用于论文主分析。
taxonomy_14_83.json与country_codes.json：分类字典和国家地区代码。
coverage.json：按来源、年份、国家和议题分组的真实覆盖量。
validation.json：去重前后数量、完整性检查、标签位置检查及待处理情况。
manifest.json：交接文件大小与SHA-256校验值。
policy_timeline*.json：沿用上一版可追溯政策事件；事件日期与新闻发表日期分别使用。

六、供后续可视化的统计口径
议题演变图：按发表年份统计议题文章量和占比，同时显示每年的来源数与样本量；可固定共同来源面板做稳健性检验。多标签议题占比之和可能超过100%。
国家和机构网络：以单篇文章为共同出现单位，单条边每篇只计一次。共同出现表达报道关联，不证明合作、冲突或因果。
议题矩阵：分别输出共现数量与Jaccard标准化值，剔除自身配对。低频单元保留样本量提示，不把稀疏标签的偶然共现写成稳定机制。
政策时间轴：用官方政策文件支持政策日期和事件名称，再关联新闻证据。仅凭同一月份或主题相似不能断言新闻报道对应某项政策。

七、论文与方法说明的边界
本次流程的可复用部分是：带时间边界的采集快照、来源级验证、可续跑检查点、原文证据地址、质量分层以及覆盖缺口补充。API采集、OCR和正则识别本身是成熟方法。论文可报告实际吞吐量、来源覆盖、去重和质量筛选结果；是否构成专利创新仍需要现有技术检索。

当前语料不是全球新闻的概率样本，早期年份、语言和出版方分布可能不均衡。自动标签尚需分层人工标注集评估精确率和召回率。不得把“已下载”“规则通过”“人工验证”三个概念混写。

八、实现依据与可引用资料
WordPress REST API官方说明：https://developer.wordpress.org/rest-api/reference/posts/ 。使用公开文章接口的content字段；date为站点时间，date_gmt为GMT时间，二者在来源元数据中区分。接口存在并不代表取得版权再分发授权。
Trafilatura官方文档：https://trafilatura.readthedocs.io/en/latest/ 。用于网页正文提取或对照；对已取得完整语义块的公开API正文，避免重复调用备用提取器。可引用：Barbaresi, A. (2021). Trafilatura: A Web Scraping Library and Command-Line Tool for Text Discovery and Extraction. ACL-IJCNLP System Demonstrations, 122–131. https://aclanthology.org/2021.acl-demo.15/ 。
RapidOCR项目文档：https://rapidai.github.io/RapidOCRDocs/ 。历史扫描页的识别模型、版本和修正记录单独保存；OCR结果不以大语言模型生成文本代替。
上述软件与接口属于既有技术。项目方法的评价应基于来源可追溯性、完整性分层、缺口补采与证据标签的实测结果，而非将通用组件本身声称为原创算法。

九、关键运行命令
在独立环境中设置PYTHONPATH为src;scripts。以下命令均在项目根目录执行；输入快照、来源配置与旧库文件的放置位置见交接说明。
python scripts/collect_global_expansion.py --minutes 120 --workers 4
python scripts/collect_global_expansion.py --minutes 120 --workers 4 --ledger extra --probes source_probes_round2.json
其他来源轮次同样通过--probes指定对应配置，不应绕过已经返回拒绝访问或限流的站点。
python scripts/label_global_expansion.py --prepare
python scripts/label_global_expansion.py --watch --minutes 240 --part 0 --parts 8
离线标注可启动0至7号分片，每个编号只能有一个活动进程；更改分片数前先停止旧进程，再运行repartition_label_cache.py保留检查点。不要在标注过程中修改分类代码。
停止采集并确认标注完成后，依次执行export_global_expansion.py --name 新快照名、audit_global_snapshot.py --snapshot 新快照名和package_global_expansion.py --snapshot 新快照名。导出器拒绝把未完成标注的输入封装为完整交付。
python scripts/run_expansion_tests.py
网络状态、出版方内容和软件版本可能变化。复现统计优先使用交接快照与校验值；重新访问网页属于新一次采集，应保留新的运行日期和版本。
