# ClimateText Lab 国际气候情报与文本数据库系统用户说明手册

版本：V1.1
适用软件：基于 AI Agent 的国际气候新闻智能分析与决策支持系统  
编制日期：2026-08-16

## 1. 软件概述

本软件面向气候谈判、外交政策研究、能源转型研究和气候新闻文本分析场景，提供国际气候新闻采集、中文编译、质量筛选、地图展示、每日简报、文本档案、语料统计分析和本地情报问答等功能。

软件采用静态网站展示与自动化数据更新相结合的方式运行。公开端重点展示可供用户阅读和研判的气候情报；采集状态、相关度分数、审核标记等内部字段仅用于后台质量控制，不在普通用户界面中展示。

## 2. 运行环境

### 2.1 本地运行环境

- 操作系统：Windows 10 及以上版本，或支持 Python 的 Linux、macOS 环境。
- Python：3.11 及以上版本。
- 浏览器：Chrome、Edge、Firefox、Safari 等现代浏览器。
- 网络：在线采集、自动更新和发布需要访问 RSS、API、GitHub Pages 等外部服务；离线预览可使用已有静态数据。

### 2.2 在线部署环境

- GitHub 仓库：用于保存代码、数据快照和自动化工作流。
- GitHub Pages：用于发布静态网站。
- GitHub Actions：用于每日定时采集、编译、导出和部署。
- 可选推送渠道：企业微信群机器人、SMTP 邮件服务。

## 3. 软件主要功能

### 3.1 全球气候现场

用户可在首页查看全球地图。地图红点表示情报明确涉及的国家或地区。用户将鼠标悬停在红点上可查看标题，点击红点可查看中文摘要、来源、发布时间和原文链接。

地图支持“今日”和“本周”两个范围：

- 今日：展示最新日入选情报的位置。
- 本周：展示最近七天入选情报的位置。

### 3.2 今日重要气候情报

系统每日自动选择约 8 至 10 条重点气候新闻。中文编译模块在来源许可及 `robots.txt` 允许时读取公开网页短正文，并结合原始标题和 RSS 短摘要生成内容；网页全文不写入公开档案。每条情报包含：

- 中文标题；
- 一句话摘要或简明摘要；
- 主题标签；
- 来源机构；
- 发布时间；
- 原文链接。

摘要强调具体事实、地区、数字或政策含义，避免展示采集状态、模型状态或无实质内容的后台说明。

### 3.3 语料分析

系统基于历史气候文本语料库生成统计图表，支持观察：

- 月度或季度新闻频率；
- 主题热度变化；
- 国家和地区分布；
- 洲别分布；
- 来源分布；
- 国家与主题交叉分布；
- 关键词共现和趋势变化。

图表用于描述当前文本样本中的报道结构，不等同于全球气候事件真实发生频率。

### 3.4 情报问答

系统提供浏览器端问答功能。用户可输入与当前气候情报相关的问题，例如：

- “今天美国和中国分别有哪些气候动态？”
- “本周能源转型相关情报有哪些？”
- “哪些事件可能影响气候谈判？”

问答模块从网站当前载入的情报和文本档案中检索证据，不调用远程模型，不产生额外模型费用。回答中涉及判断性内容时，应结合原文进一步核验。

### 3.5 文本数据库

系统维护 ClimateText-100000 文本数据库。数据库以规范化 URL 为基本记录单位，保存标题、摘要、来源、发布时间、主题、地区、国家标签、数字信息和质量标记等字段。

当前滚动档案上限为 100000 条。系统会按 URL 去重，不为凑满数量写入重复或低质量记录。

### 3.6 企业情报

能源技术模式增加可搜索的能源公司数据库和“全球企业情报现场”。企业库展示公司中英文名称、总部国家、企业类型、业务方向、官网及最新关联情报；事件分为能源巨头项目、能源初创企业和企业合作。企业地图支持“今日队列”和“本周”，定位依据会随情报展示，避免把企业总部误写成项目发生地。

### 3.7 下载今日简报

用户可点击“下载今日简报”获取 PDF 文件。PDF 内容与首页“今日重要气候情报”和问答模块中的今日简报保持一致，便于线下阅读、转发和归档。

## 4. 用户操作说明

### 4.1 访问网站

打开公开网址：

<https://generationzprogrammer.github.io/climate-agent-news/>

进入首页后，用户可依次查看全球现场、今日情报、语料分析、情报问答和文本数据库。

### 4.2 查看地图情报

1. 在首页顶部查看全球地图。
2. 点击“今日”或“本周”切换时间范围。
3. 将鼠标悬停在红点上查看简要标题。
4. 点击红点查看中文摘要和原文入口。

### 4.3 阅读今日情报

1. 滚动至“今日重要气候情报”板块。
2. 按卡片顺序阅读重点事件。
3. 如需核验事实，点击卡片中的原文链接。

### 4.4 下载简报

1. 点击页面中的“下载今日简报”按钮。
2. 浏览器将下载 PDF 文件。
3. PDF 可用于内部传阅、会议准备和资料归档。

### 4.5 使用情报问答

1. 在“情报问答”输入框中输入问题。
2. 点击提交或按回车。
3. 系统返回基于当前档案的回答和相关证据。
4. 对重大判断、数字和政策结论，应继续打开原文复核。

### 4.6 切换能源技术模式

点击页面右上角“切换到能源技术”，系统切换至能源技术视图。该模式保留相同页面结构，但内容聚焦能源转型、能源技术趋势、数字能源、储能、电网、风电、光伏和氢能等主题。再次点击右上角按钮可切回气候情报模式。

### 4.7 使用企业情报

1. 切换到能源技术模式，点击顶部“企业情报”。
2. 在能源公司数据库中输入企业名称、国家或业务关键词，并可按企业类型和国家筛选。
3. 点击企业官网或最新关联情报核验资料。
4. 在“全球企业情报现场”切换今日队列或本周，点击红点查看涉及企业、事件类别、中文概要、定位依据和原文。

### 4.8 订阅周报与查看团队信息

点击“订阅”填写邮箱。静态网站未配置安全表单端点时，浏览器会生成一封发往公开联系邮箱的订阅申请；管理员确认并将地址安全加入 GitHub Secrets 后，每周一北京时间 08:00 自动发送最近七天周报。弹窗中的“下载本周周报”可直接打开最新 PDF。点击文本数据库标题区域右侧的“团队信息”，可查看经本人明确授权公开的姓名、单位或身份、研究方向和联系邮箱。

## 5. 管理员操作说明

### 5.1 本地预览

在项目根目录执行：

```powershell
.\run.ps1
```

浏览器打开：

```text
http://127.0.0.1:8765
```

### 5.2 手动同步新闻

```powershell
.\run.ps1 sync --skip-ndc
```

如需同步官方气候文件，可去掉 `--skip-ndc`。

### 5.3 生成静态网站

```powershell
.\run.ps1 export-web --output dist
```

生成后，`dist` 目录可直接部署到静态网站服务。

### 5.4 验证发布质量

```powershell
$env:PYTHONPATH = "$PWD\src"
python -m climate_agent.cli validate-publish
```

只有通过质量门禁的数据才应发布到公开网站。

### 5.5 修复空泛摘要

当发现历史数据中存在模板化摘要时，可执行：

```powershell
python scripts\repair_generic_summaries.py
.\run.ps1 export-web --output dist
```

该脚本只替换已识别为空泛模板的摘要，不覆盖已有高质量摘要。

## 6. 数据更新机制

系统通过 GitHub Actions 每天定时运行。默认流程如下：

1. 读取启用的数据源；
2. 抓取 RSS 或 API 返回的新闻；
3. 规范化 URL 并去重；
4. 提取主题、地区、国家和数字信息；
5. 在合规允许时提取公开网页短正文，使用管理员配置的 Gemini 或其他 OpenAI 兼容模型生成忠实中文标题、实质性摘要和关注理由；
6. 合并进入新闻档案和文本数据库；
7. 生成首页数据、PDF 简报和语料分析文件；
8. 通过质量门禁后部署至 GitHub Pages。

模型输出如含“议题受到关注”等分类标题、模板套话或缺乏足够中文事实信息，将不会进入公开队列，并在后续更新中继续重试。如果某个来源连续失败，系统会记录来源健康状态，并在达到阈值后暂时隔离该来源，避免单一失败源影响整体更新。

## 7. 数据质量与使用边界

1. 本软件保存的是新闻文本线索和结构化摘要，不替代官方文件和原文核验。
2. 新闻摘要基于来源文本生成，涉及数字、承诺、责任归属和政策立场时，应打开原文确认。
3. 地理标签只在文本明确涉及国家或地区时标注；全球性文本可能保留为未标注。
4. 统计图表反映语料库中的报道频率，不代表真实事件发生频率或政策强度。
5. 系统不绕过登录、付费墙、验证码、robots.txt 或其他技术访问限制。

## 8. 常见问题

### 8.1 网站是否每天自动更新？

是。仓库配置 GitHub Actions 定时任务后，系统会每天自动采集、编译、导出并发布。若质量门禁失败，网站保留上一成功版本。

### 8.2 使用问答功能是否产生模型费用？

不会。当前网页问答在浏览器本地运行，只检索和组织站内已有情报。

### 8.3 为什么有些情报没有地图红点？

只有文本明确涉及国家或地区时才生成红点。无法可靠定位的全球性或综合性新闻不会强行标注。

### 8.4 为什么新闻数量不是每天固定 10 条？

系统优先保证质量和去重。如果当天合格新闻不足，会使用近七天高质量记录补足，但不会为了凑数加入弱相关或重复内容。

### 8.5 是否可以用于正式决策？

可作为线索筛选、议题监测和会前准备工具。正式对外表述、政策判断和引用数字前，应以原文、官方文件或人工核验结果为准。

## 9. 安全与维护建议

- 不要将 API 密钥、企业微信 Webhook、邮箱密码写入代码。
- GitHub Secrets 应仅保存必要密钥。
- 定期检查数据源健康状态和重复新闻。
- 定期抽样核验中文摘要、国家标签和数字提取结果。
- 重要会议或谈判周期前，应增加人工校对。
